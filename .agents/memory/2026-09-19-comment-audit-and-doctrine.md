# 2026-09-19 注释专项审查（workflow）+ 注释口径收紧

## 用户口径（重要，覆盖此前理解）

用户原话：「不要写画蛇添足的注释！！」——起因是我给一行改动（LocalPage 的 statusNote=""）
配了 3 行解释。**注释密度是特性 ≠ 每处都写**：只写「非显然的 WHY」，能自解释的一律不写。

判定口径（本次审查即按此执行，后续照办）：

- **该写**：跨文件逐字契约（常量必须一致的双方）、静默失败陷阱（写错不报错、
  只表现为行为异常）、反直觉取舍、历史上踩过的坑、单位/坐标系/索引顺序约定。
- **不该写**：把代码翻译成自然语言（WHAT）、复述函数名/参数、描述「本次修复/调用方是谁」
  这类会腐烂的信息、给自解释代码硬加说明。
- **必须核对**：注释描述的机制是否仍与代码一致——本仓库大量陈旧注释都是「当时对、
  后来被改掉但注释没跟着改」。

## 审查流程（用户要求「分配 workflow 审查注释」）

14 个互斥文件切片 × 2 段（审查 agent 逐行对照代码 → 对抗核实 agent 逐条推翻/确认），
28 个 agent / 约 258 万 token / 9 分钟。结果：**确认 104 条、驳回 11 条**
（驳回理由诸如「措辞粗糙非事实错误」「本仓库既定术语」「代码自解释未达误改门槛」，
说明核实环节没有盖章放行）。分档落地：

- 与代码不符 70 条、冗余 9 条 → 修复 workflow（10 切片，只改注释、各自编译校验、不提交），
  实改 87 条、8 条按边界未动。
- 该有却没有 25 条 → **主 agent 人工逐条判断后自己改**（加注释最容易画蛇添足，
  不适合交给 agent 批量执行）。

典型「不符」：core/net 多处仍写「协议唯一真源是前端 TS / 本模块尚未接线」（实际早已
wasm 接线）、core/protocol.rs 仍提废弃 iroh、ws.rs 写「指数退避重连」（实际固定 8s）。
典型「补缺」：`Color` 取值域（"empty" 是承重哨兵）、dedup 字符串表与 `is_unique` 清单
逐字一致、`board[y][x]` 索引顺序、`isComposing` 守卫、头像 128px 与接收端 20000 字符准入线、
鸿蒙 `SCHEME_HOST` 与前端 `ARKWEB_SHELL_HOST` 逐字一致、覆盖层透明靠「从不绘制」。

## 顺带暴露的两处真缺陷（不是注释问题）

1. **头像从来没有发出去过**：`MsgKind::Avatar` 在 Rust 侧只有接收分支，全仓无构造点
   （前端 `saveMyAvatar` 只落本地 + `set_avatar`）。原 UI 文案「对局开始后自动发给对手」
   是空头承诺，已改为「圆形裁剪 · 存本机」。
   **待用户拍板**：要不要真的实现头像交换（发点 + 时机，例如进对局时随首帧发）。
2. **围棋计分确认的横幅没有文案**：`score-confirm` 会进 ConfirmBanner
   （matchplay.rs 的 ConfirmKind::ScoreConfirm → snapshot `confirmReq`），但横幅只渲染
   undo/reset/swap/wrong-pwd/spec-chat 五种，用户在计分阶段看到的是「只有同意/拒绝、
   没有说明」的横幅。已补文案。

死常量，真正生效的是 `place()` 里硬编码的 30/36 —— 改为把常量传进 evaluate，契约才成立。

## 环境提示

- 用 workflow 批量改注释时，**换行风格（CRLF/LF）会让按行锚定的补丁失配**：
  脚本里要按各文件自身的换行归一化后再断言匹配（本次踩到，断言直接报错而非静默错改）。
- 只改注释也要跑全量校验：Rust doc 注释里的 ``` 围栏是 doc-test，动错会编译失败。

**Why:** 「注释密度高」被误读成「处处都要写」，正是用户反感的来源；而陈旧注释比没注释更坏
——它会让人按错的模型改代码。两者都无法靠自检发现，必须对照代码逐条核。

**How to apply:** 新写注释前先问「删掉这句，读者会不会误读/改错」；改代码后顺手核对该处
注释是否还成立（尤其机制类描述）。跨文件契约与静默失败陷阱必须写。审查脚本可复用
`comment-audit` workflow（本次脚本在会话 workflows 目录，14 切片 + 对抗核实两段）。
