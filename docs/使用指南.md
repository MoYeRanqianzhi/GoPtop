# GoPtop 使用指南

> 面向使用者的完整操作手册。项目介绍与哲学见仓库根 `README.md`；部署见 `docs/部署指南.md`；当前版本的边界与未完成项见 `docs/已知限制与路线图.md`。

GoPtop 是一个 P2P 五子棋 / 围棋应用：棋局数据只在两位对弈者的浏览器之间点对点直传（WebRTC DataChannel 端到端加密）。你需要做的只是**发一条链接**。

信令服务器是**可选**的（设置页单选，默认连官方服务器）：它负责在线名册与链接建连，数据面直连优先，直连打不通时可经服务器加密兜底中转；选择「无服务器」则完全不经服务器（纯直连模式）。

---

## 1. 打开应用

两种形态：

| 形态 | 打开方式 | 说明 |
|---|---|---|
| Web（推荐） | 浏览器访问部署站点（如 `https://goptop.pages.dev`），或本地 `npm run dev` 后访问 `http://localhost:1420` | 零安装；跨设备直连要求 HTTPS 或 localhost |
| Tauri 桌面 | `npm run tauri dev` 开发运行，或打包后的桌面应用 | 无地址栏，分享链接自动指向云端部署地址（见 6.1） |

首屏是**选项页**：本地对战 / 人机对战 / Agent 对战 / P2P 对战 / 在线用户 / 设置。

页面顶部的选择器全局切换规则与尺寸：五子棋固定 15×15；围棋 9 / 13 / 19。对局进行中锁定，需先离开对局再切换。在设置页可把当前选择保存为默认。

## 2. 本地对战与人机对战（`/local` · `/ai`）

**本地对战**：同屏双打，黑先轮流落子，先连五者胜。支持悔棋（仅本地模式）与重开。与 P2P 对战使用同一套棋盘界面。

**人机对战**（`/ai`）：本地离线 AI 对手，**不需要联网**，引擎随应用一起分发。

- 难度：状态行右侧的「快 / 标准 / 强」对应每步思考 0.3 / 1 / 3 秒。五子棋标准档约能算到 7 层；围棋档位越高落子越稳。
- 先后手：默认你执黑先行；点「换边」交换（换成 AI 执黑时它会立刻落第一手）。
- 悔棋：一次退回一个回合（你的一手 + AI 的一手），否则 AI 会立刻把同一手补回来。
- AI 想棋时界面不冻结：引擎跑在后台线程，棋盘照常缩放、按钮照常可用。

### 2.1 实时胜率（所有模式都有）

底部可在「对局 / 规则 / 胜率」之间切换（屏幕宽时「胜率」并排在「对局」卡内，点卡右上角的 ⇄ 切换）。

- **红蓝单挑线**：红色是你（本地双人 / 观战时为黑方），蓝色是对方，分界线随形势实时移动；
- **走势图**：每一手的胜率连成一条线，一眼看出形势从哪一手开始转向。

对局、人机、P2P、观战全部可用，全程本机计算、不上传任何数据。围棋胜率来自搜索统计，开局手数少时波动较大，属正常现象。

## 3. P2P 对战（核心玩法）

### 3.1 角色与流程总览

```
邀请者（先手黑）                                受邀者（后手白）
   │ ① 开启对战，复制邀请链接                     │
   │ ─────────── 邀请链接（微信/QQ/邮件…） ─────► │
   │                                            │ ② 打开链接，或在大厅「粘贴邀请链接」
   │                                            │ ③ 自动建立直连：
   │                                            │    · 顺利：直接开局，无需其他操作
   │ ◄────── 回执链接（仅跨设备且自动通道失效时）── │    · 兜底：受邀者复制回执链接发回
   │ ④ 点「输入回执」粘贴回执 → 开局              │
```

**你只需要传链接，全程不需要手动输入或复制任何技术参数（offer/answer 等都已自动编进链接）。**

### 3.2 邀请者：发起对局

1. 进入 `P2P 对战`，点 **开启对战（等对手）**。
2. 页面出现本局邀请链接，点 **复制邀请链接**，通过任意聊天工具发给对方。
3. 等待期间状态条显示「邀请已就绪 · 等待对方打开邀请链接」。

邀请链接形如 `https://<站点>/<邀请者ID>?pwd=xxxxxx&kind=gomoku&size=15&rtc=…`：

- `pwd` 是**本局钥匙**：对方凭它自动入局；两人进局后钥匙立即作废，第三人无法再用旧链接加入。
- `rtc` 是自动生成的直连信息（已压缩并混淆编码），对方打开链接即可直接建立 P2P。

### 3.3 受邀者：加入对局

两种方式任选：

- **直接打开**：在浏览器里打开收到的邀请链接。
- **弹窗粘贴**：进入 `P2P 对战` 大厅，点 **粘贴邀请链接**，把链接粘进弹窗，点 **连接**。

> 弹窗粘贴对 Tauri 桌面用户尤其重要——桌面壳里没有地址栏，收到的链接走弹窗加入。
> 解析**与域名无关**：链接被转发服务改写域名、或你手动改过域名，都能识别。

加入后自动建立 P2P 直连：

- 一切顺利：双方直接进入对局，你是白棋。
- 直连未自动打通（少数网络环境）：你的页面会自动弹出**回执弹窗**——

### 3.4 回执：跨设备直连的最后一步（兜底）

WebRTC 握手需要「offer → 受邀者」「answer → 邀请者」两次交换。邀请链接携带了前者；后者（回执）在多数网络下可经自动通道送达，**送达不了时**才需要你手动转交一次：

1. 受邀者页面自动弹出回执弹窗，点 **复制回执链接**，发给邀请者。
2. 邀请者点 **输入回执**，把回执链接粘进弹窗，确认。
3. 双方直连建立，对局开始。

回执链接同样含本局钥匙，邀请者会自动校验：钥匙不符、或你不是原邀请者，回执会被拒绝。

### 3.5 对局中

- 顶部状态条显示连接状态（「直连已建立」）与轮次；轮到你时棋盘可落子。
- **重开**：双方同步重置棋盘。
- 对局页提供**观战链接**（见第 5 节）。
- 点 **离开对局** 返回主页。

### 3.6 在线用户（`/users`）

同一浏览器内打开的多个页面会互相发现（列表显示昵称与状态）。可从列表直接发起挑战（对方弹窗同意后进局）。这是同一台设备上的辅助玩法；**连接信令服务器后，名册跨设备可见，可直接向其他设备的用户发起挑战**；无服务器模式的跨设备对弈请走 3.1 的链接流程。

## 4. Agent 对战（`/agent`，仅桌面）

菜单页「Agent 对战」进入。对面坐的不是算法 AI，而是一个**模型玩家**（LLM Agent）：它与人类玩家同权——看棋盘、落子、停一手、聊天、发起与批复悔棋、认输、确认计分；真思考、会犯错，也可能下臭棋。这与 `/ai` 的离线引擎是两回事（`/ai` 不联网、不聊天）。Agent 没有账号、不落盘，只是本局里你对面的那一席；对局本身仍是纯本地 P2P 直连（同第 3 节的链接建连模型，不经服务器）。

> 当前版本 Agent 对战**仅桌面壳可用**。浏览器（Web）与鸿蒙端进入该页只显示降级提示，功能未开放（Web 端内置模式在路线图阶段⑤，见 `docs/已知限制与路线图.md`）。

### 4.1 两种对手驱动

对局设置卡选「对手驱动」，差别只在 Agent 席由谁驱动，棋盘/聊天/协商界面完全一样：

| 驱动 | 谁在下棋 | 说明 |
|---|---|---|
| 内置（LLM 循环） | 应用内配置的 LLM | 每轮把局面与事件交给配置的模型，它经工具面落子、聊天、批复 |
| MCP（外部 Agent） | 你自己的外部 Agent（支持 MCP 的客户端，如编程助手） | 应用内嵌一个本地 MCP 服务器，外部 Agent 认领对手席驱动整局（见 4.4） |

### 4.2 对局设置

- **棋种与路数**：五子棋 15×15；围棋 9 / 13 / 19。
- **我执子**：我执黑（先行）/ 我执白。邀请方执黑，配对方向由应用自动处理。
- **对手名字**：仅聊天展示，默认「Agent」。
- 同一时刻最多一局 Agent 对战；Agent 局进行中，普通对局的开局请求会被拒绝并提示「Agent 对局进行中」。

**内置驱动的 LLM 配置**（改动即保存，「测试连接」一键验通）：

| 配置项 | 说明 |
|---|---|
| 协议 | Anthropic Messages / OpenAI Responses / OpenAI Chat Completions 三选一 |
| Base URL | 留空用协议官方默认；可指向任意兼容网关 |
| 模型 | 模型名 |
| API Key | **明文**保存在本机配置里（见第 8 节） |
| 上下文上限 | 默认 176000 tokens（可设 8000–1000000）；接近上限自动压缩历史，防上下文与成本失控 |
| 回复语言 | 任意文字（「简体中文」「English」……不校验）；留空跟随界面语言 |
| 子代理 | 默认关。开启后 Agent 可派生子代理「深思」局面，更费 token |

### 4.3 Agent 的工具面：一切皆文件

Agent 通过一个虚拟文件系统看局与行动（内置 / MCP 同一套）——**读文件=看局，写文件=行动**，工具只有文件族 read / write / edit / grep + submit：

| 路径 | 内容 |
|---|---|
| `/index` | 全部路径索引（Agent 的第一眼） |
| `/game/status` | 轮次/执色/终局/计分/待批复请求（只读，动态合成） |
| `/game/board` | 当前局面（稀疏 JSON 最省 token）；另有 `/grid`（全量 JSON）/`/ascii`/`/pretty`（模拟盘）/`/image.png` 变体 |
| `/game/rules` | 当前棋种规则全文 |
| `/game/history` | 落子历史 JSONL；`/game/history/<n>` = 第 n 手后的局面（同款变体），grep 即可回查任意手数 |
| `/game/chat` · `/game/events` | 聊天记录 · 全量事件流（只读） |
| `/game/in/move` `…/chat` `…/request` `…/confirm` `…/score` `…/resign` | **写=暂存，`submit(路径)` 才执行**（落子/发言/悔棋等请求/批复/确认计分/认输）。暂存落子以半透明「幽灵子」画在棋盘上，人能提前看到 Agent 打算下哪 |
| `/memory/…` | Agent 的长期记忆，跨局持久（本机 `~/.goptop/agent-memory.db`；内置与 MCP 两驱动分开存放） |

事件推送：内置模式下对手落子/消息/请求自动送进 Agent 的对话（无需轮询）；MCP 模式的 Agent 用 `wait_events` 工具取事件。

### 4.4 MCP 接入（仅桌面）

1. 设置卡选驱动 **MCP**，打开「MCP 服务器」开关（默认关）。服务器只监听 `127.0.0.1`，默认端口 9537（被占用自动换随机口并回显实际值），用随机 Bearer token 鉴权（可随时重新生成，旧串立即作废）。
2. 点 **复制 .mcp.json 连接串**，粘进外部 Agent 的 MCP 配置：

```json
{
  "mcpServers": {
    "goptop": {
      "url": "http://127.0.0.1:9537/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

3. 选棋种/执色，点 **开始对局**；页面显示「等待 MCP Agent 接入」。外部 Agent 调 `game_start` 认领对手席后自动开局，`game_leave` 或认输收尾。棋种/路数/执色以页面配置为权威，外部 Agent 无权改。

> MCP 客户端建议调大单工具超时：Agent 的 `wait_events` 一次最多阻塞等 120 秒（等你的落子/消息）。

### 4.5 对局视图与停止

对局中页面 = 棋盘 + 聊天（同 P2P）+ **Agent 状态卡**：状态（配对中 / 思考中 / 等待你的行动 / 已终局 / 出错）、拟落子预览、LLM 调用数与输入输出 token、压缩次数、工具日志、**停止对局**（Agent 认输并终止）。围棋进入计分时死子由你单方标记（Agent 不参与标死子，它会自动确认计分）。

### 4.6 已知限制与注意事项

- **平台**：仅桌面壳。Web / 鸿蒙未开放；MCP 依赖本机 TCP 监听，天然仅桌面。
- **密钥明文**：API Key 明文存于本机 `~/.goptop/store.json`，请自行注意保管。
- **成本**：内置 Agent 每轮都携带上下文请求 LLM，长局持续消耗 token；已有上下文上限+自动压缩、单局 LLM 调用硬上限（240 次）与状态卡实时 token 计量兜底，仍建议留意用量。MCP 模式的 LLM 成本发生在你外部 Agent 的一侧。
- Agent 的 MCP 服务器只监听本机回环地址，且有随机 token 保护；不要把端口暴露到局域网之外。

## 5. 观战

- **服务器模式（默认，跨设备可用）**：邀请者在对局页点 **邀请观战 / 复制观战链接**，得到形如 `https://<站点>/<邀请者ID>?pwd=<观战钥匙>&spec=1` 的链接。任何设备打开即可实时同步观棋（只读）；观战钥匙每局生成、整局有效，房主可随时关闭观战。
- **无服务器模式（同源可用）**：观战链接形如 `https://<站点>/watch/<对局ID>`，目前仅**同一浏览器**内打开可用（实时同步落子，只读）。跨设备观战在路线图中（届时同样走「回执」模型），详见 `docs/已知限制与路线图.md`。

**观战房间管理（服务器模式）**：观战者凭钥匙入局；钥匙不对或没带钥匙的打开者会转为聊天区里的**私有申请**，由对局者批准后入局。双方对局者共同维护观战房间：可**禁言/解除禁言**、**踢出**观战者、**关闭观战**；观战者默认只读，申请发言需**两位对局者都批准**后才能发言。

## 6. 设置（`/settings`）

| 设置项 | 说明 |
|---|---|
| 昵称 | 在在线用户列表中显示；留空则显示 ID 前几位 |
| 默认规则与尺寸 | 新对局的默认选择，保存后生效 |
| 我的身份 | 本页的随机用户 ID（每开一个新标签页/窗口都会生成新身份），可从这里打开「我的主页」 |
| 信令服务器 | 官方 / 自建 / 无服务器**单选**切换，同一时刻只连一台；可添加自建地址（`wss://…/ws`）。选服务器带来在线名册、跨设备免回执链接与兜底中转；不同服务器之间无法对战 |
| 头像 | 在「我的主页」（设置页「我的身份」→ 打开我的主页）上传或清除，自动圆形裁剪；对局与聊天中展示，并经 P2P 与对方交换 |
| 直连线路（STUN） | 打洞用的地址发现节点，见下 |

### 6.1 STUN 直连线路

STUN 只做 NAT 地址发现（「问路」），**不转发任何棋局数据**。内置 9 条线路（默认启用前三条，其余默认关闭）：

| 名称 | 地址 | 默认 |
|---|---|---|
| 小米 | `stun:stun.miwifi.com:3478` | 开 |
| 哔哩哔哩 | `stun:stun.chat.bilibili.com:3478` | 开 |
| Cloudflare | `stun:stun.cloudflare.com:3478` | 开 |
| Google | `stun:stun.l.google.com:19302` | 关 |
| Twilio | `stun:global.stun.twilio.com:3478` | 关 |
| Nextcloud | `stun:stun.nextcloud.com:443` | 关 |
| Sipnet | `stun:stun.sipnet.ru:3478` | 关 |
| Cope | `stun:stun.cope.es:3478` | 关 |
| wtfismyip | `stun:stun.wtfismyip.com:3478` | 关 |

可开关任一线路、添加自定义 STUN（格式 `stun:host:port`）。全部关闭时仅剩局域网直连（host 候选）。

> **Tauri 桌面用户注意**：桌面应用里生成的分享链接自动指向云端部署地址（默认 `https://goptop.pages.dev`）。这是自动行为，无需也不会提供设置入口。

## 7. 疑难解答

**直连失败 / 一直「连接中」？**
1. 确认双方页面都是 HTTPS（或 localhost）。
2. 设置页检查至少启用一条 STUN 线路；公司/校园网可能封 UDP，换网络或换线路再试。
3. 对称型 NAT（常见于企业网/部分 4G/5G）下无 TURN 中转即无法打洞——这是纯 P2P 的天性，换网络是唯一解。
4. 使用兜底路径：让受邀者发回执链接，邀请者「输入回执」。

**回执粘贴后提示「钥匙与本局不符」？**
回执与邀请必须来自同一局。邀请者取消等待后重新开战，旧回执即作废——请对方重新走一遍流程。

**同一浏览器开两个窗口自己和自己下？**
可以，但这是边缘玩法；请优先在两个真实设备间对弈。

**邀请链接打开后是空白主页？**
链接可能被聊天工具截断。改用「粘贴邀请链接」弹窗，整段复制粘贴。

## 8. 我的数据存在哪

昵称、头像、服务器列表、STUN 线路、默认规则/尺寸都保存在**本机**（不上传服务器）：

| 你用的端 | 存放位置 |
|---|---|
| 网页版 | 浏览器本地存储（换浏览器/清站点数据会丢） |
| Windows 桌面壳 | 用户目录下的 `~/.goptop/store.json`（即 `C:\Users\<你>\.goptop\store.json`） |
| 安卓 App | 应用私有数据目录内（系统设置里「清除数据」或卸载即清除） |
| 鸿蒙 App | 应用私有文件目录内（同上） |

退出应用、重启电脑都不影响；想备份或迁移，直接拷这个文件即可。

桌面壳下 Agent 对战（第 4 节）的配置（含 LLM API Key）也在 `store.json` 里；Agent 的长期记忆库另存为同目录下的 `~/.goptop/agent-memory.db`。
