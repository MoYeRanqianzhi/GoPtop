# GoPtop 使用指南

> 面向使用者的完整操作手册。项目介绍与哲学见仓库根 `README.md`；部署见 `docs/部署指南.md`；当前版本的边界与未完成项见 `docs/已知限制与路线图.md`。

GoPtop 是一个**无服务器**的 P2P 五子棋 / 围棋应用：棋局数据只在两位对弈者的浏览器之间点对点直传（WebRTC DataChannel 端到端加密），不经任何服务器中转。你需要做的只是**发一条链接**。

---

## 1. 打开应用

两种形态：

| 形态 | 打开方式 | 说明 |
|---|---|---|
| Web（推荐） | 浏览器访问部署站点（如 `https://goptop.pages.dev`），或本地 `npm run dev` 后访问 `http://localhost:1420` | 零安装；跨设备直连要求 HTTPS 或 localhost |
| Tauri 桌面 | `npm run tauri dev` 开发运行，或打包后的桌面应用 | 无地址栏，分享链接自动指向云端部署地址（见 4.4） |

首屏是**选项页**：本地对战 / P2P 对战 / 在线用户 / 设置。

页面顶部的选择器全局切换规则与尺寸：五子棋固定 15×15；围棋 9 / 13 / 19。对局进行中锁定，需先离开对局再切换。在设置页可把当前选择保存为默认。

---

## 2. 本地对战（`/local`）

同屏双打：黑先轮流落子，先连五者胜。支持悔棋（仅本地模式）与重开。与 P2P 对战使用同一套棋盘界面。

---

## 3. P2P 对战（核心玩法）

### 3.1 角色与流程总览

```
房主（先手黑）                                客人（后手白）
   │ ① 开启对战，复制邀请链接                     │
   │ ─────────── 邀请链接（微信/QQ/邮件…） ─────► │
   │                                            │ ② 打开链接，或在大厅「粘贴邀请链接」
   │                                            │ ③ 自动建立直连：
   │                                            │    · 顺利：直接开局，无需其他操作
   │ ◄────── 回执链接（仅跨设备且自动通道失效时）── │    · 兜底：客人复制回执链接发回
   │ ④ 点「输入回执」粘贴回执 → 开局              │
```

**你只需要传链接，全程不需要手动输入或复制任何技术参数（offer/answer 等都已自动编进链接）。**

### 3.2 房主：发起对局

1. 进入 `P2P 对战`，点 **开启对战（等对手）**。
2. 页面出现本局邀请链接，点 **复制邀请链接**，通过任意聊天工具发给对方。
3. 等待期间状态条显示「邀请已就绪 · 等待对方打开邀请链接」。

邀请链接形如 `https://<站点>/<房主ID>?pwd=xxxxxx&kind=gomoku&size=15&rtc=…`：

- `pwd` 是**本局钥匙**：对方凭它自动入局；两人进局后钥匙立即作废，第三人无法再用旧链接加入。
- `rtc` 是自动生成的直连信息（已压缩并混淆编码），对方打开链接即可直接建立 P2P。

### 3.3 客人：加入对局

两种方式任选：

- **直接打开**：在浏览器里打开收到的邀请链接。
- **弹窗粘贴**：进入 `P2P 对战` 大厅，点 **粘贴邀请链接**，把链接粘进弹窗，点 **连接**。

> 弹窗粘贴对 Tauri 桌面用户尤其重要——桌面壳里没有地址栏，收到的链接走弹窗加入。
> 解析**与域名无关**：链接被转发服务改写域名、或你手动改过域名，都能识别。

加入后自动建立 P2P 直连：

- 一切顺利：双方直接进入对局，你是白棋。
- 直连未自动打通（少数网络环境）：你的页面会自动弹出**回执弹窗**——

### 3.4 回执：跨设备直连的最后一步（兜底）

WebRTC 握手需要「offer → 客人」「answer → 房主」两次交换。邀请链接携带了前者；后者（回执）在多数网络下可经自动通道送达，**送达不了时**才需要你手动转交一次：

1. 客人页面自动弹出回执弹窗，点 **复制回执链接**，发给房主。
2. 房主点 **输入回执**，把回执链接粘进弹窗，确认。
3. 双方直连建立，对局开始。

回执链接同样含本局钥匙，房主会自动校验：钥匙不符、或你不是原房主，回执会被拒绝。

### 3.5 对局中

- 顶部状态条显示连接状态（「直连已建立」）与轮次；轮到你时棋盘可落子。
- **重开**：双方同步重置棋盘。
- 对局页提供**观战链接**（见下一节）。
- 点 **离开对局** 返回主页。

### 3.6 在线用户（`/users`）

同一浏览器内打开的多个页面会互相发现（列表显示昵称与状态）。可从列表直接发起挑战（对方弹窗同意后进局）。这是同一台设备上的辅助玩法；**跨设备请走 3.1 的链接流程**。

---

## 4. 观战

- 观战链接：房主在对局页点 **邀请观战 / 复制观战链接**，得到 `https://<站点>/watch/<对局ID>`。
- **当前版本**：同一浏览器内打开观战链接可用（实时同步落子，只读）。
- **跨设备观战尚未实现**：在其他设备打开观战链接目前看不到棋局。该能力在路线图中（届时同样走「回执」模型）。详见 `docs/已知限制与路线图.md`。

---

## 5. 设置（`/settings`）

| 设置项 | 说明 |
|---|---|
| 昵称 | 在在线用户列表中显示；留空则显示 ID 前几位 |
| 默认规则与尺寸 | 新对局的默认选择，保存后生效 |
| 我的身份 | 本页的随机用户 ID（每开一个新标签页/窗口都会生成新身份） |
| 直连线路（STUN） | 打洞用的地址发现节点，见下 |

### 4.4 STUN 直连线路

STUN 只做 NAT 地址发现（「问路」），**不转发任何棋局数据**。内置线路：

| 名称 | 地址 | 默认 |
|---|---|---|
| 国服A区 | `stun.miwifi.com:3478` | 开 |
| 国服B区 | `stun.chat.bilibili.com:3478` | 开 |
| 外服 | `stun.l.google.com:19302` | 关（国内多不可用，备用） |

可开关任一线路、添加自定义 STUN（格式 `stun:host:port`）。全部关闭时仅剩局域网直连（host 候选）。

> **Tauri 桌面用户注意**：桌面应用里生成的分享链接自动指向云端部署地址（默认 `https://goptop.pages.dev`）。这是自动行为，无需也不会提供设置入口。

## 6. 疑难解答

**直连失败 / 一直「连接中」？**
1. 确认双方页面都是 HTTPS（或 localhost）。
2. 设置页检查至少启用一条 STUN 线路；公司/校园网可能封 UDP，换网络或换线路再试。
3. 对称型 NAT（常见于企业网/部分 4G/5G）下无 TURN 中转即无法打洞——这是纯 P2P 的天性，换网络是唯一解。
4. 使用兜底路径：让客人发回执链接，房主「输入回执」。

**回执粘贴后提示「钥匙与本局不符」？**
回执与邀请必须来自同一局。房主取消等待后重新开战，旧回执即作废——请对方重新走一遍流程。

**同一浏览器开两个窗口自己和自己下？**
可以，但这是边缘玩法；请优先在两个真实设备间对弈。

**邀请链接打开后是空白主页？**
链接可能被聊天工具截断。改用「粘贴邀请链接」弹窗，整段复制粘贴。
