# GoPtop 已知限制与路线图

> 诚实清单：本文档只记录**当前版本真实存在**的限制，逐项标注状态。修完一项删一项，不许出现文档超前于实现的情况。

更新日期：2026-09-15（Rust 化第二阶段落地后；修完一项删一项）

---

## A. 连接与联机

### A1. 对局数据面断线无自动重连 —— 未实现，路线图内
- 现状：服务器信令面有自动重连（指数退避 + 状态重放）；但对局 DataChannel 断开后需重走邀请/回执流程，对局进度不恢复（对局卡亮红「已中断」）。
- 计划：基于对局历史（`history`）的续局重连。

### A2. 对称型 NAT 下无法直连 —— P2P 天性，不会修复（服务器模式可兜底中转）
- 现状：双方都在对称型 NAT（常见于企业网、部分 4G/5G）后时，无 TURN 中转即无法打洞，直连失败。
- 设计立场：**不引入 TURN**。直连优先；服务器模式的加密兜底中转是用户主动选择连服时才存在（服务器纯转发、不落地），无服务器模式宁断不转。换网络是唯一解；应用内已在失败时给出提示。

## B. 规则引擎

### B1. 五子棋无禁手规则 —— 设计取舍
- 无三三/四四/长连禁手（无禁手自由规则）。
- 围棋打劫（简单劫）、双 Pass 终局、区域计分（中国规则贴 7.5 目）、死子标记与双确认计分已于 2026-09-15 全部实现（`crates/goptop-core`，全端生效）。

## C. 平台与部署

### C1. Tauri 桌面版联机依赖云端部署地址 —— 设计如此
- 桌面壳没有自己的公网地址，分享链接自动指向 `shareOrigin`（Web=当前站点 origin；Tauri=云端部署常量，见 `frontend/src/net/links.ts` 的 `shareOrigin()`）。自建部署需改该常量。刻意**不提供**用户级设置入口（避免用户误设导致链接不可达）。

### C2. 每个标签页独立身份 —— 设计如此
- 用户 ID 存 `sessionStorage`：新开标签页即新身份。同浏览器多页互见（在线用户/观战/双开）均基于此。

### C3. 前端 TS 层仍保留少量传输相邻代码 —— 迁移收尾项
- 现状：协议/信令/状态机/编解码/链接解析已全部在 Rust（`crates/goptop-net` + `goptop-transport`，经 wasm 运行）；TS 侧保留 `net/links.ts`（UI 展示用链接拼接/导航）、`net/identity.ts`（昵称读取）、`net/servers.ts`（设置读取）、`game/rules.ts`（本地对局的规则 wasm 绑定薄壳）。
- 路线：本地对局也改走 WasmSession 后删除 rules.ts；导航逻辑随路由下沉评估。
